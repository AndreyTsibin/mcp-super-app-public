# Карта сервера: что видит пользователь и как попадает к каждому тулу

> Составлено 2026-08-17 (v0.3.0) по живому ответу сервера на `tools/list`, а не по памяти.
> Проверять так: `printf '…initialize…\n…tools/list…\n' | node dist/index.js`.

## Главное различие: «нет в меню» ≠ «недоступен»

Сервер отдаёт клиенту **все 9 тулов всегда**. Claude видит их список целиком и в любой
момент может вызвать любой — ничего не спрятано на уровне протокола.

Ограничено только **меню**: инструкции сервера (`src/index.ts`) запрещают агенту
перечислять всё подряд по фразе «запусти mcp-super-app» и велят показать 3 точки входа.
Это сделано ради самого пользователя: список из девяти технических названий заставляет
выбирать инструмент вместо того, чтобы сказать, чего он хочет.

**Отсюда правило: до любого тула вне меню добираются словами.** «Поставь скилл
diagram-design», «найди иконку корзины», «сожми картинки в папке assets» — агент
подберёт тул сам, потому что видит их все.

## Что происходит по фразе «запусти mcp-super-app»

```
«запусти mcp-super-app»
        │
        ▼
  один AskUserQuestion — 3 пункта (4-й появляется, только когда вышла новая версия)
        │
        ├─ bootstrap_project ──── агент спрашивает бриф в чате:
        │                         название, стек, что строим, профиль S/M/L, путь
        │
        ├─ create_website ─────── второй вопрос: kind?
        │                          ├─ landing    — лендинг из библиотеки секций
        │                          └─ multipage  — переделка существующего сайта-донора
        │
        ├─ create_image ───────── провайдер по умолчанию openrouter;
        │                         magnific — только если пользователь сам назвал Magnific
        │                         (и только если в .env есть MAGNIFIC_API_KEY)
        │
        └─ ⚠️ Обновить сервер до vX.Y.Z ── появляется, когда self-check видит свежий тег
                                            в origin; вызывает update_server, затем рестарт
```

## Все девять тулов

| Тул | В меню | Обязательные параметры | Как до него добраться |
|---|---|---|---|
| `bootstrap_project` | да | `project_path`, `name`, `profile` (S/M/L), `stack`, `vision` | пункт меню |
| `create_website` | да | `kind` (landing/multipage), `project_path` | пункт меню |
| `create_image` | да | `prompt`, `prompt_source` | пункт меню |
| `update_server` | условно | — | пункт меню, когда есть обновление; или «обнови сервер» |
| `install_skill` | нет | `skill`, `project_path` | «поставь скилл `<имя>`»; зовётся и внутри флоу |
| `install_guard` | нет | — (по умолчанию `target: user`) | «поставь защиту от опасных команд» |
| `search_icons` | нет | `query` | «найди иконку …» |
| `get_icon` | нет | `set` (lucide/simple-icons), `name` | «дай иконку …» — обычно после `search_icons` |
| `optimize_images` | нет | `paths` | «сожми картинки в …»; зовётся в конце image-пайплайна лендинга |

### Каталог скиллов для `install_skill`

`clean-user-facing-text`, `diagram-design`, `frontend-design`, `fullstack-architect`,
`humanizer-ru`, `image`, `remove-ai-marks`, `ui-ux-pro-max`, `emil-design-skills`.

Назначение каждого — в описании параметра `skill` у самого тула: агент читает его сам,
гадать по названию не нужно.

## Почему шесть тулов не в меню

Не потому, что второсортные, а потому что **у них нет самостоятельного сценария**:

- `install_skill`, `optimize_images` — вызываются внутри флоу точек входа
  (`bootstrap_project` ставит скиллы, лендинг в конце жмёт картинки). Пользователь
  приходит не за «установить скилл», а за проектом или сайтом.
- `search_icons` / `get_icon` — нужны посреди вёрстки, а не в начале работы.
- `install_guard` — разовая настройка окружения, а не задача.
- `update_server` — обслуживание; поэтому и появляется в меню только когда действительно
  есть что обновлять.

Ограничение AskUserQuestion — максимум 4 варианта, так что «показать всё» технически и
не получится: три входа плюс обновление уже занимают весь лимит.

## Если нужно вынести тул в меню

Меню — это текст в `instructions()` (`src/index.ts`), а не конфиг. Порядок такой:

1. добавить строку в блок «Точки входа» (по образцу `updateLine()` — условный пункт);
2. пересобрать (`npm run build`) и **перезапустить сессию**: клиент читает инструкции
   ровно один раз, при `initialize`;
3. помнить о цене — инструкции оплачиваются токенами в КАЖДОЙ сессии, поэтому меню
   держат коротким, а лимит AskUserQuestion всё равно 4 пункта.

Прежде чем выносить: проверь, что у тула есть сценарий, с которого пользователь НАЧИНАЕТ
работу. Если он всегда идёт следом за чем-то — ему в меню не место, достаточно того, что
агент видит его в списке и зовёт по ситуации.
