# Карта инструментов mcp-super-app

Руководство пользователя. mcp-super-app — локальный MCP-сервер для Claude Code. Он добавляет
в чат девять инструментов: каркас проекта, среду сайта, генерацию и оптимизацию картинок,
установку скиллов, защиту от разрушительных команд и поиск иконок. Ниже — что делает каждый
инструмент, какие скиллы он за собой тянет и в каком порядке всё это вызывать.

Сервер локальный: работает на твоей машине, файлы создаёт в твоих папках, наружу уходят
только запросы генерации картинок.

---

## Три точки входа и шесть помощников

Инструменты делятся на два класса. **Точки входа** — то, с чего начинается работа: их просят
словами («сделай каркас проекта», «нарисуй картинку»). **Помощники** вызываются по ходу дела,
обычно самим агентом.

Проще всего сказать в чат **«Запусти mcp-super-app»** — Claude предложит выбрать точку входа.

### `bootstrap_project` — каркас нового проекта

1. **Бриф** в чате: название, стек, профиль S / M / L, одно-два предложения о том, что строим.
2. **Скелет:** `.gitignore`, `.claude/` (настройки, хук передачи между сессиями, страж
   документации), `docs/` по профилю, авто-память проекта.
3. **Документация с первого дня:** журнал решений `docs/decisions/`, заготовки трекера
   и скоупа с форматом внутри, бюджеты контекста в `CLAUDE.md`.
4. **Скиллы:** на M / L ставит `fullstack-architect`, остальные предлагает списком.
5. **Защита:** проверяет глобальный guard и ставит, если его нет.

### `create_website` — среда для сайта, два режима

- **`kind = landing`** — Astro плюс библиотека из 21 секции, токены темы, страницы-превью
  `/kit` и `/themes`, лид-форма, машинный валидатор вёрстки.
- **`kind = multipage`** — перенос существующего сайта на Astro: плейбук, лид-форма,
  трекер. Источником может быть свой сайт на конструкторе (Tilda, Wix, WordPress),
  свой макет из Figma или чужой сайт-донор. В первой сессии человек выбирает режим:
  точная копия один в один или редизайн по чужому донору. Скелет поднимается позже,
  когда источник изучен.
- Оба режима ставят 5 скиллов и пишут `docs/_dev/tracker.md` — одна задача на сессию.

### `create_image` — генерация и правка изображений

1. Скилл `image` пишет промпт под конкретную модель — **без него инструмент откажет и денег
   не потратит**.
2. Генерация: OpenRouter (по умолчанию) или Magnific, если добавлен его ключ.
3. `optimize_images` — обязательный последний шаг: ресайз, webp, srcset.

## Все девять инструментов

| Инструмент | За что отвечает | Когда вызывается |
|---|---|---|
| **`bootstrap_project`** *(вход)* | Создаёт каркас нового проекта за один вызов: `.gitignore`, `.editorconfig`, папку `.claude/` (настройки, хук, `CLAUDE.md`, файл передачи между сессиями), `docs/` по глубине профиля и авто-память проекта. На профилях M и L ставит скилл `fullstack-architect`. | Начало нового проекта. Бриф собирается в чате: название, стек, профиль S / M / L, одно-два предложения о цели. |
| **`create_website`** *(вход)* | Готовит рабочую среду сайта и трекер задач. `landing` — проект Astro с библиотекой из 21 секции, контрактом токенов, страницами-превью, шаблонами формы заявки и машинным валидатором вёрстки. `multipage` — методичка по переносу существующего сайта на Astro (точная копия или редизайн), без готового шаблона. | Когда нужен сайт. Режим выбирает человек: строим с нуля или переносим существующий сайт — свой с конструктора, свой макет или чужой донор. |
| **`create_image`** *(вход)* | Генерирует и редактирует изображения, возвращает картинку прямо в чат, сохраняет файл и показывает реальную стоимость кадра. Правка идёт через `reference_images` плюс инструкция в промпте. Требует промпт, написанный скиллом `image`. | «Нарисуй», «сгенерируй картинку», «поменяй фон на этом кадре». Нужен ключ OpenRouter в `.env` сервера. |
| `optimize_images` | Готовит картинки к публикации: уменьшает до нужной ширины (по умолчанию 1920 px, никогда не растягивает), переводит в webp (или jpeg / avif), исправляет поворот по EXIF, при необходимости делает набор размеров для `srcset`. Возвращает итоговые размеры для атрибутов `width` и `height`. | Сразу после того, как вся серия картинок сгенерирована. Одним вызовом на всю папку, не между кадрами. |
| `install_skill` | Ставит любой скилл из каталога в проект — в папку `.claude/skills/`. Часть скиллов вшита в сервер и копируется как есть, часть ставится их собственным установщиком, чтобы приходила свежая версия. Существующие файлы не затираются. | Когда проекту нужен конкретный навык: промпты картинок, чистка текста, диаграммы, дизайн. |
| `install_guard` | Ставит защиту от необратимых команд: перехватчик блокирует удаление файлов, `git reset --hard`, `git clean -f` и `push --force`, пропуская безопасные варианты. Ставится глобально или в один проект. | Обычно не вручную: `bootstrap_project` сам проверяет глобальную защиту и ставит её, если её нет. |
| `search_icons` | Ищет иконки по английскому слову в двух локальных наборах: lucide (около 2000 интерфейсных) и simple-icons (около 3400 логотипов компаний). | Перед `get_icon`, чтобы узнать точное имя иконки. |
| `get_icon` | Отдаёт готовый SVG-код одной иконки по точному имени, с нужным размером и цветом. | Когда имя иконки уже известно и её надо вставить в вёрстку. |
| `update_server` | Обновляет сам сервер: подтягивает изменения из репозитория, доустанавливает зависимости и пересобирает. Отказывается работать, если в папке сервера есть незакоммиченные правки. | Когда сервер сообщает о доступном обновлении. После обновления приложение нужно перезапустить. |

## Скиллы: что умеет каждый

Скилл — это инструкция, которую агент читает перед работой определённого типа. Вшитые
копируются из сервера и работают без интернета; внешние ставятся своим установщиком, поэтому
приходят всегда свежей версии.

| Скилл | Тип | Для чего |
|---|---|---|
| `image` | вшитый | Пишет промпт под конкретную модель и подбирает аргументы размера. Обязателен для `create_image` — у каждой модели свой синтаксис, и ошибка в размере стоит денег. |
| `humanizer-ru` | вшитый | Убирает из русского текста следы машинного письма: канцелярит, цепочки родительных падежей, «является», кальки с английского, тире-связку. Только русский язык. |
| `clean-user-facing-text` | вшитый | Финальная гигиена текста: находит и вырезает невидимые символы Юникода и экзотические пробелы, затем переписывает прозу, не трогая факты, код, пути и цитаты. Нужен `python3`. |
| `remove-ai-marks` | вшитый | Снимает метки происхождения с твоих собственных файлов: невидимый Юникод, C2PA / EXIF / XMP у картинок и документов. Требует отдельно запущенного сервиса очистки — без него честно останавливается с ошибкой. |
| `diagram-design` | вшитый | Рисует схемы и графики как самостоятельные HTML-файлы: архитектура, блок-схемы, последовательности, таймлайны, воронки. Перерисовывает исходники из drawio и Mermaid. Добавляет четыре слэш-команды. |
| `frontend-design` | вшитый | Задаёт визуальное направление интерфейса, чтобы результат не выглядел шаблонной AI-вёрсткой: палитра, типографика, композиция. |
| `fullstack-architect` | вшитый | Превращает идею в проектную документацию: требования → архитектура → план → задачи. Два режима: пошаговый для нетехнического человека и быстрый для разработчика. |
| `ui-ux-pro-max` | внешний | Крупные дизайн-решения: стили, палитры, пары шрифтов, выбор стека. Ставится своим установщиком. |
| `emil-design-skills` | внешний | Мелкая моторика интерфейса: тайминги анимаций, физика движения, принципы Apple. Дополняет предыдущий. |

### Какой инструмент какие скиллы приносит

Скиллы не нужно ставить вручную по одному: точки входа тянут за собой ровно то, что нужно их
сценарию. Отдельно ставят только то, чего не хватило.

| Инструмент | Ставит скиллы | Почему именно эти |
|---|---|---|
| `bootstrap_project` | `fullstack-architect` — на профилях M и L. Остальной каталог предлагает списком с описаниями, выбор за человеком. | Профиль S — это лендинг или скрипт, там документация избыточна и работа идёт сразу в код. |
| `create_website` | `ui-ux-pro-max`, `frontend-design`, `emil-design-skills`, `humanizer-ru`, `image` — оба режима, пять сразу. | Сайт — это одновременно дизайн, анимация, русский текст и картинки. Каждая часть закрыта своим скиллом. |
| `create_image` | `image` — проверяет наличие, при отсутствии ставит сам и отказывается генерировать, пока промпт не пройдёт через скилл. | Промпт «в лоб» даёт худший кадр за те же деньги. Проверка стоит ноль, ошибка — реальные центы. |
| `install_skill` | Любой из девяти по имени. | Ручной способ, когда сценарий нестандартный. |

> **Главное правило.** Скиллы, команды и настройки загружаются только при старте сессии.
> После любой установки нужно перезапустить сессию Claude Code — иначе новый скилл просто не
> будет виден. Инструменты сами об этом напоминают в отчёте.

## Модели картинок и цена кадра

Цены измерены по фактическим счетам OpenRouter, а не взяты из прайса. Выбор модели начинается
с одного вопроса: кадр пойдёт к реальной аудитории или это черновик?

| Модель | Цена кадра | Размер | Когда брать |
|---|---|---|---|
| `gpt-5.4-image-2` | $0.035 | 1536×864 | Значение по умолчанию. Черновики, референсы, «просто покажи вариант». Самый дешёвый кадр и лучший реализм в своей ценовой группе. |
| `gemini-3.1-flash-image` | $0.101 | 2752×1536 | Всё, что увидит клиент. Лучшая кожа и материалы, узкие баннерные пропорции. Серия для сайта — 3–5 кадров, то есть 30–50 центов. |
| `seedream-5-0-lite` | $0.035 | 3642×2048 | Правка и серии. Цена не зависит от размера, а правка кадра стоит вчетверо дешевле, чем на модели по умолчанию. |
| `gemini-3-pro-image` | $0.137 | 2752×1536 | Только тяжёлые сцены: много взаимодействующих объектов, сложная физика. Не «кнопка сделать лучше». |

Если правки запланированы заранее — начинай серию на `seedream` и оставайся на ней. Правка на
модели по умолчанию стоит около $0.140 за вызов: исходная картинка оплачивается как входные
данные.

## Маршрут «текст + картинка для карточки товара»

Типовой поток, если задача — регулярно готовить объявления: текст, изображение и файлы,
готовые к загрузке на площадку.

1. **Каркас.** `bootstrap_project` с профилем S — папка проекта, правила и память, без лишней
   документации.
2. **Навыки.** `install_skill` для `image`, `humanizer-ru` и `clean-user-facing-text`.
   Затем перезапуск сессии.
3. **Текст.** Пишешь черновик объявления, скилл `humanizer-ru` убирает машинный стиль,
   `clean-user-facing-text` делает финальную чистку символов.
4. **Картинка.** Скилл `image` собирает промпт → `create_image` генерирует кадр. Первый кадр
   серии становится образцом: его передают в `reference_images` для остальных, чтобы все
   снимки выглядели из одной съёмки.
5. **Подготовка файлов.** `optimize_images` одним вызовом на всю папку: вес падает в разы,
   размеры приходят в отчёте.
6. **Публикация.** За пределами сервера: готовые тексты и файлы забирает твой скрипт или API
   площадки — инструмента публикации в mcp-super-app нет.

## Что нужно один раз настроить

Установка описана по шагам в [INSTALL.md](../INSTALL.md) — там же готовый промпт, который
можно просто отправить в чат. Коротко:

```bash
git clone <репозиторий> && cd mcp-super-app
npm install
npm run build
claude mcp add mcp-super-app -s user -- node /абсолютный/путь/dist/index.js
```

- **Node.js 20 или новее.** На 18 работает всё, кроме автоматической подгрузки ключа
  для картинок.
- **Ключ OpenRouter** нужен только для `create_image`. Лежит в файле `.env` в папке сервера,
  в конфиг клиента его передавать не надо. Остальные восемь инструментов работают без ключей.
- **Ничего не затирается.** Все инструменты идемпотентны: существующие файлы не
  перезаписываются, а попадают в отчёт как пропущенные. Повторный вызов безопасен.
