# Решения: доставка обновлений

Релизы, две копии репозитория, синк, CI. Формат и правила — `README.md`.

### DLV-1 · Изменение существует для пользователя только в публичном `main`
`релизы` `процесс`
**Грабли:** порт в публичную копию делался по инициативе агента. Пользователь узнаёт об
обновлении, сравнивая свой чекаут с origin — значит изменение, не доехавшее до публичного
`main`, для него не существует. Забыли синк = коллеги месяцами на старом, и никакого сигнала
об этом не приходит.
**Решение:** порт встроен в `scripts/release.mjs` и не может быть забыт. Релизы — по
накоплению, а не на каждую фазу.
_2026-08-17_

### DLV-2 · `rsync` без `--checksum` врёт про изменения
`sync`
**Грабли:** сухой прогон синка сказал «изменений содержимого нет», хотя lock-файлы копий
различались тремя версиями. rsync решает по паре (размер, mtime), а версии в lock поменялись
без изменения размера. Файл размечался флагом `t` и уезжал в счётчик «выравнивание дат» —
содержимое копировалось, но ревьюеру в глаза не попадало.
**Решение:** `--checksum`; изменённое содержимое помечается `c`, у реально совпадающих
остаётся только `t`.
_2026-08-17_

### DLV-3 · Правила `rsync` без ведущего слеша матчатся на любой глубине
`sync`
**Грабли:** `README.md`, `INSTALL.md`, `docs/_dev/` и `scripts/` были перечислены в исключениях
без ведущего слеша. Под них молча попадали части шаблонов, которые обязаны ехать:
`assets/landing/site/src/assets/img/README.md`, трекеры `assets/<шаблон>/docs/_dev/tracker.md`,
`assets/bootstrap/docs/architecture/INSTALL.md`. И `--delete` их не чистил — исключённое не
удаляется, поэтому в публичке они жили в том виде, в каком доехали при первом ручном порте.
**Решение:** правила заякорены на корень (`/README.md`). `--include` идут перед соответствующими
`--exclude`: rsync применяет правила по порядку, поэтому `/.env.example` едет, а `.env` нет.
_2026-08-17_

### DLV-4 · `INSTALL.md` и `README.md` синком не переносятся намеренно
`sync` `эксплуатация`
Публичное «лицо» написано под чужую аудиторию. Правишь инструкцию — обновляй оба репозитория
руками.
_2026-09-01_

### DLV-5 · Force-push не убирает секрет из публичного репозитория
`безопасность`
**Грабли:** из шаблона вычистили хост CRM. Схлопывание истории в один коммит + force-push
оказалось недостаточным: старые коммиты **остаются доступны по прямому SHA** — проверено,
отдавались.
**Решение:** репозиторий удалён через веб-интерфейс и создан заново; все пять старых SHA
теперь отдают `422 No commit found`.
**Не делать:** не считать переписанную историю зачисткой утечки.
_2026-07-29_

### DLV-6 · Валидатор лендинга в CI не запускается
`ci`
Он валидирует готовый сайт, а шаблон по определению состоит из маркеров `[[…]]`, картинок-
заглушек и `site: example.com`. Прогон на чистом шаблоне даёт 6 ошибок и 4 предупреждения —
вечно красная джоба, которую перестают читать. Поломку компонента или импорта ловит сама сборка.
_2026-08-17_

### DLV-7 · `update_server` показывает CHANGELOG, а не коммиты
`ux` `релизы`
Английские conventional-commits точны для разработчика и бесполезны для аудитории сервера.
Тул сравнивает `CHANGELOG.md` до и после обновления и выводит появившиеся секции версий; нет
файла — фолбэк на список коммитов. Отсюда требование: раздел `## Не выпущено` пишется
по-русски и для пользователя — этот текст он увидит дословно.
_2026-08-17_

### DLV-8 · Отдельный релизный чекаут отменён
`процесс` `отложено`
MCP зарегистрирован прямо на рабочую папку (`~/.claude.json` → `node …/dist/index.js`),
отдельной установки у Андрея нет: обновление = `npm run build` + рестарт приложения. Пока
сервер правится каждую сессию, мгновенная обратная связь важнее, чем воспроизводить опыт
коллеги. Вернуться, когда правки станут редкими.
_2026-08-17_

### DLV-9 · `release.mjs --apply` требует явного разрешения Андрея
`эксплуатация`
Пуш в `main` и теги auto-классификатор Claude Code блокирует. Команду запускает Андрей или
агент с разрешением в чате — сама по себе она не проходит.
_2026-08-17_

### DLV-10 · GitHub push protection роняет пуш из-за плейсхолдера ключа
`безопасность` `публичка`
**Грабли:** `.env.example` с плейсхолдером вида `sk-or-v1-xxxx…` — сканер GitHub считает его
настоящим ключом OpenRouter и отбивает пуш (GH013).
**Решение:** в образце пустое значение `OPENROUTER_API_KEY=`.
**Мина:** в ПРИВАТНОМ репозитории старый плейсхолдер мог остаться — выстрелит, если репозиторий
когда-нибудь станет публичным.
_2026-07-27_

### DLV-11 · Тег обязателен в обоих репозиториях
`релизы`
`origin` у коллеги — публичка; `self-check` берёт доступную версию из `ls-remote --tags origin`
и сравнивает с `package.json` чекаута. Без тега в публичке пользователь снова увидит «ветка
ушла вперёд на N коммитов» вместо номера версии. `release.mjs` ставит тег в обе копии.
Мерж в `main` — именно `--no-ff`: ветки разошлись, прошлые релизы тоже merge-коммиты.
_2026-08-17_

### DLV-12 · Кто ставился до 2026-07-29 — сидит на выпиленном `launch.sh`
`эксплуатация` `windows`
Обёртка была bash-скриптом и на Windows не запускалась вовсе. Её убрали, сервер регистрируется
напрямую: `claude mcp add mcp-super-app -s user -- node <АБСОЛЮТНЫЙ_ПУТЬ>/dist/index.js`
(путь только абсолютный, `~` не разворачивается — конфиг глобальный). У поставившихся раньше
после обновления файла не будет и сервер не стартует: им нужна ПЕРЕрегистрация, а не только
`git pull`.
_2026-07-29_

### DLV-14 · Домашнюю папку спрашивают у рантайма, а не у оболочки
`windows` `эксплуатация` `установка`
**Грабли:** установка проходит, агент рапортует «готово», после рестарта клиент говорит, что
сервера нет. Инструкция допускала три способа промахнуться мимо клиента, и все три чаще
всего срабатывают в десктопном приложении, а не в терминале: `~` в Git Bash при доменном
профиле или перенаправлении папок указывает на сетевой диск (`H:\`), а клиент читает
`os.homedir()` = `C:\Users\Имя`; регистрация «от имени администратора» уходит в чужой
профиль; при отсутствии `claude` в PATH (у GUI-установки его нет по умолчанию) прежний
fallback разрешал проектный `.mcp.json` — он живёт ровно в одной папке.
**Правило:** домашняя папка берётся у того рантайма, который будет читать конфиг
(`node -e "console.log(require('os').homedir())"`), скоуп — только user, а `claude mcp list`
со статусом `connected` — обязательный шаг: без него агенту запрещено говорить «готово».
**Не подтверждено:** какая именно из трёх причин сработала у команды на Windows Server —
диагностику с их машин не собрали, починены все три сразу.
_2026-09-02_
