# Решения: платформа

ОС, пути, хуки, guard, `.gitignore`, папка памяти Claude Code. Формат и правила — `README.md`.

### PLT-1 · Хуки запускаются exec-формой, а не строкой команды
`windows` `hooks` `claude-code`
**Грабли:** хук, записанный строкой (`bash "${CLAUDE_PROJECT_DIR}/…/hook.sh"`), на Windows
не работал вовсе: оболочки другие, кавычки и пробелы в пути ломают разбор, а guard'у вдобавок
нужен `jq`, которого там нет. Защита молча становилась fail-open.
**Решение:** exec form — `{"command": "node", "args": [...]}`. Claude Code запускает node
напрямую, без оболочки, поэтому bash/PowerShell, кавычки и пробелы перестают участвовать.
Сами хуки — на node. Глобальный guard пишет абсолютный путь (его `settings.json` никуда не
едет), проектный хук — `${CLAUDE_PROJECT_DIR}`, чтобы репозиторий оставался переносимым.
**Не делать:** не полагаться на наличие shell-утилит (`jq`, `sed`) в хуке — у половины
аудитории их нет, а падение хука выглядит как «защита есть».

### PLT-2 · Расширение хука — `.mjs`, а не `.js`
`windows` `hooks` `esm`
**Грабли:** хук ставится в ЧУЖОЙ проект, где `package.json` может быть каким угодно или
отсутствовать. `.js` там читается то как CommonJS, то как ESM — по чужому `"type"`.
**Решение:** `.mjs` — ESM всегда, независимо от манифеста проекта.
_2026-09-01_

### PLT-3 · Слаг папки памяти повторяет правило хоста буквально
`windows` `memory` `paths`
**Грабли:** `projectSlug` заменял только `/`. На Windows `path.resolve` отдаёт
`D:\Kefir\aviparser` — заменять нечего, строка уезжала в `path.join` целиком, получалось
`C:\…\projects\D:\Kefir\…` с двоеточием в середине. Такой каталог Windows не создаёт →
`bootstrap_project` падал с `ENOENT`. На macOS тот же баг тише: у проектов с точкой или
подчёркиванием в пути память писалась мимо папки, из которой читает Claude Code.
**Решение:** `[^a-zA-Z0-9]` → `-`, как делает сам хост. Проверено по 373 папкам в
`~/.claude/projects`: `_` там тоже становится `-`, папок с точкой нет ни одной.
**Не делать:** не выводить слаг «логично» (заменить разделители пути) — правило хоста
грубее, и расходиться с ним нельзя ни в одном символе, иначе память уходит в чужую папку.
_2026-09-01_

### PLT-4 · Покрытие пути в `.gitignore` спрашивают у git, а не у строк
`gitignore` `install_skill`
**Грабли:** живой баг в `landing-page-generator`. Его `.gitignore` игнорил скиллы через
`.claude/skills/*` плюс три `!`-негации на версионируемые скиллы. `install_skill` искал в
файле буквальную строку `.claude/skills/`, не нашёл и дописал её в конец. Директорийная форма
исключает папку целиком — **git внутрь не заходит, и все негации умирают молча**. Три скилла
выпали из репозитория, откат руками.
**Решение:** перед дописыванием паттерна строится probe-путь (для директорийных форм —
фиктивный файл внутри, для файловых — сам путь) и по нему выполняется `git check-ignore -q --`.
Exit 0 = уже покрыто. Фолбэк на буквальное сравнение, если git не запустился или это не
репозиторий (exit 128).
**Не делать:** не перечислять формы записи одного и того же смысла — их десяток, и вопрос
изначально не про строки, а про семантику. Спрашивать надо у того, кто её и определяет.
_2026-08-17_

### PLT-5 · Слэш-команды скилла живут в `.claude/commands/`, не внутри скилла
`skills` `claude-code`
**Грабли:** bundled-скилл `diagram-design` несёт свои слэш-команды. Внутрь папки скилла их
класть нельзя — Claude Code читает команды только из `.claude/commands/`.
**Решение:** payload команд лежит отдельно (`assets/commands/<skill id>/*.md`) и ставится в
`.claude/commands/`. Там же продолжают резолвиться относительные ссылки `../skills/<id>/…`
в их телах. В `.gitignore` команды пишутся пофайлово: паттерн `.claude/commands/` целиком
проглотил бы и команды самого проекта.
_2026-08-17_

### PLT-6 · Guard блокирует тексты про деструктивные команды
`guard` `эксплуатация`
**Грабли:** PreToolUse-хук смотрит на подстроку в команде. Heredoc, внутри которого написано
правило про удаление файлов, содержит эту подстроку — и guard блокирует запись собственной
документации.
**Решение:** такие файлы писать инструментом Write, а не `cat <<EOF`.
_2026-09-01_

### PLT-7 · Скиллы, команды и хуки грузятся только на старте сессии
`claude-code` `эксплуатация`
После `install_skill`, `bootstrap_project` и `create_website` нужен рестарт сессии — иначе
поставленное не видно и выглядит как «тул не сработал». `.claude/rules/` подхватываются сразу,
без рестарта — это единственное исключение.
_2026-08-17_

### PLT-8 · Инструкции для модели проверяются прогоном, а не чтением
`проверка` `скиллы` `headless`
**Грабли:** правки в скилле и в MCP-instructions — это текст для модели: тесты его не
исполняют, `npm test` остаётся зелёным при любой чепухе. Фаза 20 закрылась с правками
`fullstack-architect`, которые ни разу не выполнялись; читая их глазами, пять дефектов
(BST-6…BST-8, SRV-11 и пустой `scope.md`) не видно ни одного.
**Решение:** гонять сценарий в отдельной сессии Claude Code, играя пользователя:
```bash
claude -p "<реплика человека>" --session-id "$(uuidgen | tr 'A-Z' 'a-z')" \
  --setting-sources project,local \                 # отрезает личные CLAUDE.md и скиллы
  --mcp-config mcp.json --strict-mcp-config \        # только наш сервер, как у коллеги
  --append-system-prompt "$(cat rule.txt)" \         # правило, которое ставит INSTALL.md
  --permission-mode bypassPermissions \
  --output-format stream-json --verbose > run.jsonl
```
Дальше `--resume <id>` для каждой следующей реплики; «перезапуск сессии» — новый
`--session-id` в той же папке. `stream-json` хранит вызовы тулов с аргументами и `usage`,
так что из лога считаются и поведение, и цена, и размер контекста.
**Не делать:** не проверять в своей же сессии — свой `~/.claude/CLAUDE.md` подмешивает
и стиль, и правила (в первом прогоне он выдал новичку YAGNI-лекцию про amoCRM), а личные
скиллы создают инструменты, которых у коллеги нет.
**Цена:** полный сценарий «пустая папка → каркас → проектирование → закрытие сессии» —
12 подсессий, $8.6, около часа.
_2026-09-01_
