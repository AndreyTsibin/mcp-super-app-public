# Журнал решений

Что выяснили на практике, чтобы не наступать повторно. Сюда переезжает **durable-знание**:
почему решено так, найденная ловушка, замеренная цена, грабли эксплуатации. Операционный лог
(«сделал X, N тестов, коммит») сюда не идёт — его помнит git.

**Читать перед заходом в подсистему**, грепом по теме, а не целиком.

## Как искать

Оглавления тут нет намеренно — второй слой правды устаревает независимо от записей:

```bash
grep -rn "^### " docs/decisions/          # все записи
grep -rn "windows" docs/decisions/        # по тегу или слову
```

## Файлы

| Файл | Префикс ID | О чём |
|---|---|---|
| `bootstrap.md` | `BST` | каркас проектов: что разворачивается в чужом проекте и почему |
| `platform.md` | `PLT` | ОС, пути, хуки, guard, `.gitignore`, память Claude Code |
| `server.md` | `SRV` | схемы и описания тулов, MCP-instructions, самопроверки, эвалы |
| `images.md` | `IMG` | OpenRouter, выбор моделей, замеры цены |
| `delivery.md` | `DLV` | релизы, две копии репозитория, синк, CI |
| `sites.md` | `SITE` | шаблоны лендинга и multipage, заявки, иконки |

## Формат записи

```markdown
### PLT-7 · Короткая суть одной строкой
`тег` `тег`
**Грабли:** что сломалось и как выглядел симптом.
**Решение:** что сделали и почему именно так.
**Не делать:** способ, который выглядит правильным, но не работает.
_2026-09-01_
```

ID = префикс файла + номер внутри файла, сквозной нумерации нет. Номера не переиспользуются:
запись устарела — правится или сносится вместе с номером.

**Не пиши сюда** то, что выводится из кода или git-истории: статусы задач (это трекер),
списки файлов, структуру модулей, «что было сделано».
