# Установка mcp-super-app

Инструкция из двух частей. **Часть 1** — что делает человек руками (три шага, ничего
технического). **Часть 2** — текст, который человек копирует целиком и отправляет в
Claude Code; дальше агент ставит сервер сам. **Часть 3** — подробности для агента:
он читает их из этого же файла после того, как склонирует репозиторий.

---

# Часть 1 — для человека

Нужен установленный [Claude Code](https://claude.com/claude-code) и Node.js 20 или
новее (<https://nodejs.org>, кнопка LTS). Больше ничего заранее ставить не нужно.

1. **Создай пустую папку** — где угодно, хоть в «Документах». Название любое,
   например `mcp-super-app`.
2. **Открой в ней Claude Code.** В приложении — «Open folder» и выбери созданную папку.
   В терминале — зайди в неё (`cd путь/к/папке`) и запусти `claude`.
3. **Скопируй текст из части 2 целиком и отправь его в чат.** Дальше агент всё сделает
   сам: проверит окружение, скачает сервер, соберёт, подключит и объяснит, что получилось.

Что делать во время установки: агент может спросить, нужна ли тебе генерация картинок
(она платная и требует своего ключа) и куда ставить сервер. Отвечай обычными словами.
Технических вопросов он задавать не должен — если задаёт, так и скажи ему.

В конце агент попросит **перезапустить Claude Code**. Это обязательно: без перезапуска
новые инструменты не появятся.

# Часть 2 — скопируй это в Claude Code

```text
Установи мне MCP-сервер mcp-super-app. Я не разработчик: не задавай мне технических
вопросов, не проси лезть в конфиги, объясняй простыми словами и делай всё сам.

1. Определи, на какой я системе — macOS или Windows — и дальше выполняй шаги для неё:
   пути, команды и способ установки Node различаются. Не предполагай macOS по умолчанию.

2. Проверь, что стоит Node.js 20+ и git. Если чего-то нет — скажи, как поставить,
   и дождись, пока я это сделаю.

3. Склонируй репозиторий в текущую папку:
   git clone https://github.com/AndreyTsibin/mcp-super-app-public.git .

4. Открой файл INSTALL.md из склонированной папки, найди в нём «Часть 3 — подробная
   инструкция для агента» и выполни её по шагам.

5. Если по дороге что-то падает — не останавливайся на первой ошибке: разберись и
   почини сам (права, PATH, кавычки в путях, отсутствующие зависимости, уже занятое
   имя MCP-сервера). Останавливайся и спрашивай меня только там, где нужно моё
   решение или мой ключ.

6. Запиши в мой глобальный файл ~/.claude/CLAUDE.md (на Windows —
   C:\Users\<Имя>\.claude\CLAUDE.md) и в мою глобальную память такое правило:

   «Когда я пишу в чат "Запусти mcp-super-app" или похожую фразу про mcp-super-app —
   не перечисляй все инструменты. Задай мне вопрос через AskUserQuestion (режим Asking)
   и предложи только точки входа: bootstrap_project (каркас нового проекта),
   create_website (сайт: лендинг или переделка существующего), create_image
   (генерация картинок). Если сервер сообщает о доступном обновлении — добавь
   четвёртым пунктом "Обновить сервер".»

   Файл не перезаписывай: допиши правило в конец, остальное содержимое сохрани.

7. Когда закончишь, собери короткий отчёт об установке: моя ОС и версии Node/git, что
   встало, какие ошибки встретились и как ты их починил, что осталось нерешённым.
   Покажи отчёт мне. Если в нём есть ошибки или неудобства — спроси меня, можно ли
   отправить его разработчику, и только после моего согласия создай issue:
   gh issue create --repo AndreyTsibin/mcp-super-app-public --title "..." --body "..."
   Если gh не установлен или я откажусь — просто сохрани отчёт в файл
   install-report.md в папке сервера и скажи мне, что его можно переслать разработчику
   вручную.
```

# Часть 3 — подробная инструкция для агента

Ты устанавливаешь локальный MCP-сервер `mcp-super-app` на машину пользователя.
Пользователь скорее всего **не разработчик**. Объясняй простыми словами, что происходит,
и делай сам.

**Сначала определи систему** — от неё зависят все пути и часть команд:

| | macOS / Linux | Windows |
|---|---|---|
| Домашняя папка | `~` → `/Users/имя` | `%USERPROFILE%` → `C:\Users\Имя` |
| Абсолютный путь к серверу | `/Users/имя/mcp-super-app/dist/index.js` | `C:\Users\Имя\mcp-super-app\dist\index.js` |
| Установка Node | `brew install node` | скачать с <https://nodejs.org> или `winget install OpenJS.NodeJS.LTS` |
| Проверить, где ты | `pwd` | `cd` (без аргументов) |

Если шаг падает — почини сам, где это в твоих силах. Останавливайся только там, где
нужно решение пользователя. Всё, что чинил, запиши для итогового отчёта (шаг 7).

### Шаг 1 — проверь окружение

```bash
node -v
git --version
```

Нужен **Node.js 20 или новее**. Если Node нет или он старее 20 — скажи об этом
пользователю и предложи поставить (см. таблицу выше). Git — с <https://git-scm.com>.
Дальше не иди, пока Node не встанет.

### Шаг 2 — склонируй репозиторий

Если пользователь уже открыл пустую папку под сервер (обычный случай — так написано
в части 1), клонируй прямо в неё:

```bash
git clone https://github.com/AndreyTsibin/mcp-super-app-public.git .
```

Папка не пустая или пользователь просил другое место — ставь в домашнюю папку
(`~/mcp-super-app`, на Windows `%USERPROFILE%\mcp-super-app`). Если такая папка уже
существует — не перезаписывай: зайди в неё и сделай `git pull`.

### Шаг 3 — установи зависимости и собери

```bash
npm install && npm run build
```

Должна появиться папка `dist/` с файлом `index.js` — проверь, что он на месте.

Частые причины падения на этом шаге: старый Node (см. шаг 1), нет прав на запись в
папку, оборванная сеть на `npm install` (просто повтори). Чини и продолжай.

### Шаг 4 — подключи сервер к Claude Code

```bash
claude mcp add mcp-super-app -s user -- node <АБСОЛЮТНЫЙ_ПУТЬ>/dist/index.js
```

Флаг `-s user` = сервер доступен во всех проектах, а не только в текущем.

**Подставь настоящий абсолютный путь**, не `~` и не относительный: конфиг хранится
глобально и разворачивается не из той папки, где ты сейчас стоишь. Узнай путь заранее
(`pwd` / `cd`) и подставь целиком — например `/Users/имя/mcp-super-app/dist/index.js`
на macOS или `C:\Users\Имя\mcp-super-app\dist\index.js` на Windows.

Если команда ругается, что сервер с таким именем уже есть — сначала
`claude mcp remove mcp-super-app -s user`, потом повтори.

Нет команды `claude` (Claude Code стоит не как CLI) — подключи сервер файлом:
`~/.claude.json` (глобально) или `.mcp.json` в корне проекта, см. раздел
«Подключение к Claude Code вручную» в [README.md](README.md). На Windows в JSON
обратные слэши экранируются: `"C:\\Users\\Имя\\mcp-super-app\\dist\\index.js"`.

### Шаг 5 — ключ OpenRouter (только если нужна генерация картинок)

Инструмент `create_image` требует свой ключ OpenRouter. Все остальные инструменты
работают без каких-либо ключей.

Спроси пользователя, нужна ли ему генерация картинок.

- **Не нужна** → пропусти шаг, всё уже готово.
- **Нужна** → объясни, что нужно:
  1. Завести аккаунт на <https://openrouter.ai>, пополнить баланс (генерация платная,
     порядка \$0.04 за картинку) и создать ключ на <https://openrouter.ai/keys>.
  2. Создать файл `.env` в папке сервера и вписать в него одну строку:

     ```
     OPENROUTER_API_KEY=свой-ключ-сюда
     ```

  **Ключ пользователь вписывает сам** — не проси его диктовать ключ тебе в чат.
  Можешь создать `.env` из шаблона (`cp .env.example .env`, на Windows
  `copy .env.example .env`) и сказать, какую строку в нём заменить.

`.env` лежит в `.gitignore` — в репозиторий он не утечёт.

### Шаг 6 — правило вызова сервера в глобальном CLAUDE.md

Допиши в конец `~/.claude/CLAUDE.md` (Windows: `C:\Users\<Имя>\.claude\CLAUDE.md`)
блок ниже. Файл не перезаписывай — существующее содержимое сохрани; если файла нет,
создай его. Если у пользователя включена глобальная авто-память, сохрани то же правило
и туда.

```markdown
## mcp-super-app

Когда пользователь пишет «Запусти mcp-super-app» или похожую фразу про mcp-super-app —
не перечисляй все инструменты. Задай вопрос через AskUserQuestion и предложи только
точки входа:
- `bootstrap_project` — каркас нового проекта;
- `create_website` — сайт: `landing` (лендинг из библиотеки секций) или `multipage`
  (переделка существующего сайта);
- `create_image` — генерация картинок.

Если сервер сообщил о доступном обновлении — добавь четвёртым пунктом «Обновить сервер»
и вызови `update_server`, если пользователь его выберет.
```

### Шаг 7 — проверь и отчитайся

Скажи пользователю: **перезапустить Claude Code** (закрыть и открыть заново) — без
этого новый сервер не подхватится.

После перезапуска в любом чате должны быть доступны инструменты `bootstrap_project`,
`install_skill`, `create_website`, `install_guard`, `create_image`, `optimize_images`,
`search_icons`, `get_icon`. Список подключённых серверов: `claude mcp list`.

Собери короткий отчёт: ОС и версии Node/git, что установлено и куда, какие ошибки
встретились и как ты их починил, что осталось нерешённым. Покажи его пользователю.

Если в отчёте есть ошибки или неудобства — **спроси разрешение** и только после
согласия отправь разработчику:

```bash
gh issue create --repo AndreyTsibin/mcp-super-app-public \
  --title "Установка на <ОС>: <короткая суть>" --body "<отчёт>"
```

Нет `gh`, нет авторизации или пользователь отказался — сохрани отчёт в
`install-report.md` в папке сервера и скажи, что его можно переслать разработчику
вручную. Ключи, токены и личные пути из отчёта убери.

## Что делать, если не заработало

| Симптом | Причина и что делать |
|---|---|
| Инструментов нет в чате | Claude Code не перезапущен. Закрой и открой заново. |
| `Cannot find module .../dist/index.js` | Не прошёл `npm run build`. Повтори шаг 3. |
| `command not found: claude` | Claude Code стоит не как CLI. Подключи сервер вручную — см. «Подключение к Claude Code вручную» в [README.md](README.md). |
| Сервер не стартует, путь с `~` | `~` в конфиге не разворачивается. Перерегистрируй с абсолютным путём (шаг 4). |
| `create_image` ругается на ключ | Нет `.env` или в нём неверный ключ. См. шаг 5. |
| На Windows пути с пробелами ломают команду | Оберни путь в кавычки целиком: `node "C:\Users\Имя Фамилия\mcp-super-app\dist\index.js"`. |

## Обновление до свежей версии

**Сервер сам скажет, когда выйдет новая версия.** При старте он сверяется с репозиторием
и, если что-то вышло, сообщает об этом — а на фразу «запусти mcp-super-app» добавляет в
меню пункт «Обновить сервер до vX.Y.Z». Проверка кэшируется на сутки; нет сети или git —
сервер молча стартует как обычно.

Обновиться: **скажи Claude Code «обнови mcp-super-app»**. Он вызовет тул `update_server`,
который сам подтянет изменения, при необходимости переустановит зависимости, пересоберёт
сервер и покажет, что нового. Дальше **перезапусти Claude Code** — сервер это запущенный
процесс, новый код подхватывается только при старте.

Тул отказывается работать, если в папке сервера есть незакоммиченные правки — чужую работу
он не трогает. `.env` с ключом никогда не страдает: он не в git.

### Если сервер поставлен давно

У старых установок тула `update_server` ещё нет — обновиться нужно один раз руками
(точнее, попросить Claude Code выполнить):

```bash
cd ~/mcp-super-app && git pull && npm install && npm run build
```

Дальше всё работает само. Если `git pull` ругается, что перемотка невозможна
(`not possible to fast-forward`), значит история репозитория переписана — пусть агент
синхронизирует ветку с `origin/main` жёстко и пересоберёт. Папку удалять не нужно.

Совсем старые установки (до августа 2026) регистрировали сервер через файл `launch.sh`.
Его больше нет, и после обновления сервер просто не стартует. Лечится перерегистрацией:

```bash
claude mcp remove mcp-super-app -s user
claude mcp add mcp-super-app -s user -- node /АБСОЛЮТНЫЙ/ПУТЬ/mcp-super-app/dist/index.js
```
