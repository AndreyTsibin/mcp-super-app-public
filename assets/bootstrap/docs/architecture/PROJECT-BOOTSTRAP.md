# 🚀 Project Bootstrap — принципы метода (почему так)

> **Это референс «почему», не инструкция «как».** Разворачивает проект агент по
> [INSTALL.md](INSTALL.md) — там пошаговое «как». Здесь — решения и их обоснования,
> чтобы при правках установщика было видно, какой принцип нельзя ломать.
> Установщик кладёт этот файл в `docs/architecture/` как справочник проекта.

---

## Метод: архитектор-исполнитель

Ты придумываешь продукт (что это, как работает, что даёт пользователю) — Claude Code
реализует (как построено). Отсюда растут два следствия ниже: **автономия решений** и
**жёсткий cold-start** между сессиями. Без них метод не работает: либо тебя дёргают
вопросами по коду, в которых ты не участвуешь, либо каждая сессия начинается с нуля.

## Порядок: фундамент → доки → инструменты → код

Сначала правила и конфиги, потом документация, потом инструменты агента, только потом код.
**Почему:** код, написанный до того как зафиксированы правила и скоуп, переписывается.
Дешевле договориться на берегу, чем рефакторить под задним числом введённый стандарт.

## Масштаб по профилю (S / M / L)

Глубина каркаса = масштабу проекта: **S** (лендинг/скрипт) — минимум, **M** (приложение) —
ядро + архитектура, **L** (продукт) — полный набор. **Почему:** структура крупного продукта,
вываленная на статичный лендинг, — это пустые папки и мёртвые разделы, то есть мусор. От
малого к большому дорастить тривиально; раздутое на пустом месте только мешает. (INSTALL, Шаг 0/3.)

## Глубина по фазам

Текущий этап документируем детально, отложенные — крупными мазками или заглушками.
**Почему:** детальная спека на то, что ещё сто раз поменяется, — выкинутый труд.

## Git-флоу соло: коммитим в `develop` напрямую

`develop` — рабочая ветка, `main` — только релизы (`develop → main`). Без feature-веток и PR.
**Почему:** для соло feature-ветки и ревью-церемонии — чистый оверхед. Дисциплину держим не
ветками, а **чекпоинт-коммитами по ходу** (чистый коммит = откат неудачного хода без боли)
и Conventional Commits на английском. Пуш — только с явного разрешения (исключение: протокол завершения сессии — там пуш штатный).

## CLAUDE.md — это инструкции агенту, а не оглавление

`.claude/CLAUDE.md` содержит правила поведения (commands, architecture, conventions, git),
на английском, до 200 строк; на `docs/` ссылается по пути. **Почему:** так это определяет
Anthropic — файл грузится в контекст каждой сессии как поведенческий контракт. Карта-таблица
со ссылками тратит контекст впустую и не меняет поведение агента. Детальная дока живёт в
`docs/` и читается по надобности, не висит в контексте. (INSTALL, Шаг 4.)

## Cold-start: память + handoff + SessionStart-хук

Главная цель метода — **каждую новую сессию начинать с готового контекста из прошлых**.
Три опоры: (1) `MEMORY.md` + `work-protocol` — постоянные правила; (2) `.claude/HANDOFF.md` —
нарратив «где встали», пишется в конце сессии; (3) **SessionStart-хук** впрыскивает handoff
в начало каждой сессии. **Почему хук, а не просто память:** память модель может проигнорировать,
хук подаёт контекст детерминированно — «железобетонно». `work-protocol` ставится всегда, даже
на профиль S. (INSTALL, Шаг 2/5.)

## Автономия решений: КАК — Claude, ЧТО — ты

Реализацию (структура кода, паттерны, инфра, схема данных, нейминг, рефакторинг) Claude
решает сам по best practices, поясняя выбор одной строкой. Тебе выносится только: критичное/
необратимое с ценой (деньги, прод-данные, безопасность, смена стратегии), UI (когда есть визуал),
функционал (что фича даёт пользователю). **Почему:** развилки по коду ты оценить не можешь и не
хочешь — они бесполезны и тормозят. Код пишет Claude → Claude и отвечает за решения по нему.

## Трекеры: фича целиком, не раздельно бэк/фронт

Мастер-трекер → трекеры по модулям/фичам, внутри фичи чек-пункты «бэк / фронт / тесты».
**Почему:** раздельные бэк- и фронт-трекеры для соло дают рассинхрон — фича висит наполовину
закрытой в двух местах. Одна фича = один атомарный кусок, закрывается целиком.

## Скиллы — не в шаблоне

Установщик намеренно не тащит скиллы (`fullstack-architect`, `frontend-design`, `humanizer-ru`…).
**Почему:** у каждого свой набор под свои задачи; вшитые скиллы делают шаблон непереносимым.
Подключаешь сам как plugin/skill в Claude Code.

## CodeGraph — когда появился костяк кода

Локальный knowledge-graph проекта (символы, связи, call-graph): агент находит код через граф,
а не грепом — меньше токенов и round-trip'ов. **Почему не сразу:** на голых доках индексировать
нечего, ставим когда есть реальный код. Не входит в установщик — это пост-установочный шаг:

```bash
curl -fsSL https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.sh | sh
codegraph install -t claude -l global -y    # MCP в Claude Code, глобально
codegraph init                              # индекс в корне проекта
```
После — рестарт Claude Code (MCP подцепится), `.codegraph/` в `.gitignore` (индекс машинно-локальный).
