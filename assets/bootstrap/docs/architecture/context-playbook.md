# Плейбук контекста — инструкция для Claude Code

> **Кому.** Этот файл читает Claude Code, не человек. Разработчик положил его в проект и попросил
> «прочитай и выполни» — возможно, без единого слова контекста. Прочитай целиком, затем исполняй §0.
> **Зачем.** Документация и память проекта растут линейно, контекст — нет. Всё, что ты читаешь
> «на всякий случай», вытесняет нужное по задаче и прямо роняет качество работы. Ниже — как
> устроить знание проекта, чтобы деградации не было, и как дальше следить за этим самому.
> **Версия** 2.0 (2026-09-17). Механика проверена на Claude Code 2.1.238 и 2.1.266 (macOS).
> Метка ✅ = проверено экспериментом на живом проекте, а не выведено из документации; при
> расхождении с твоими представлениями верь ✅. Цифры «до → после» с того же проекта: cold start
> 9 178 → 6 859 токенов, трекер + субтрекер 18 483 → 3 917, память 45 файлов → 19, протухших
> путей к коду 35 → 0.

## 0. Режим исполнения

**Сначала проверь, не развёрнут ли проект уже по этому плейбуку.** Признаки: `CLAUDE.md` с
картой документации, файл handoff вместе с SessionStart-хуком, страж документации в
репозитории. Всё это есть — внедрять нечего, и §0 исполняется как **сверка**: чего из §4–§7
здесь не стоит и нужно ли оно этому проекту. Фактические пути бери из карты документации в
`CLAUDE.md`, а не из примеров ниже: handoff и страж могут лежать в `.claude/`, плейбук — в
корне `docs/`, это то же самое другими путями. Завести второй файл рядом с работающим —
худшее, что можно сделать по этому тексту.

Дальше — для проекта, где ничего этого нет. Порядок жёсткий:
**обследовать → согласовать → настроить → включить постоянный режим.**

1. **Обследование, ничего не менять.** Что есть: `CLAUDE.md` (где лежит, размер), `.claude/`
   (rules, skills, hooks, settings), `docs/`, трекеры, handoff-подобные файлы, git, стек (чем
   проект запускает скрипты), каталог памяти из твоего системного промпта
   (`~/.claude/projects/<проект>/memory/`). Замерить cold start и вторую волну (§4). Найти
   антипаттерны (§8).
2. **Отчёт и план, один экран:** цифры, найденное, масштаб внедрения (§10.0), список файлов,
   которые создашь и изменишь. Ждать согласия. Если человек заранее сказал «делай без вопросов» —
   идти дальше, план всё равно показать.
3. **Настройка по §10.** Существующее не переписывать молча — показывать diff. Не удалять без
   явного согласия. Не создавать того, что проекту сейчас не нужно.
4. **Постоянный режим:** протокол §6 — в `CLAUDE.md` проекта, стражи §7 — в хук и в гейт тестов.
   Этот файл переместить в `docs/_dev/context-playbook.md`: он нужен раз в фазу, не каждую
   сессию. Никогда не делать его `CLAUDE.md` и не `@`-импортировать.
5. **Итог:** цифры до/после и что осталось за человеком (например, выполнить `/context`).

**Кроссплатформенность обязательна:** проект живёт на macOS и Windows. Скрипты — на стеке
проекта, не на bash; пути — через `/`; ничего, что требует отдельной установки. Хук — в
exec-форме (§10.7): без шелла, одинаково на обеих ОС.

## 1. Два бюджета

| Бюджет | Что это | Типичная ошибка |
|---|---|---|
| **Cold start** | Грузится каждую сессию до первой строки задачи: `CLAUDE.md` (глобальный + проектный), безусловные `rules`, индекс памяти, описания скиллов, имена MCP-инструментов, впрыск SessionStart-хука | Оптимизируют только его — он на виду |
| **Вторая волна** | Что сессия читает, чтобы понять, ЧТО делать: трекер, субтрекер, спека подсистемы | Не считают вообще. На живом проекте вышла **вдвое дороже** cold start ✅ |

Сначала мерь и режь вторую волну: раздутый трекер съедает больше, чем весь `CLAUDE.md`, и
платится на каждой сессии по той же фиче.

## 2. Слои знания

Каждый файл отвечает на один вопрос и имеет срок жизни. Не отвечает — мусор.

| Слой | Отвечает на вопрос | Когда читается | Когда умирает |
|---|---|---|---|
| `.claude/CLAUDE.md` | Как работать с этим репозиторием: стек, команды, конвенции, протоколы, карта документации | Всегда | Живёт всегда, но не растёт: детали уезжают в слои ниже |
| `.claude/rules/*.md` с `paths:` | Правила для конкретной части кода | Только при чтении совпавших файлов | Вместе с частью кода |
| `docs/_dev/HANDOFF.md` | Где встали, что дальше, что читать | Всегда (хук) | Перезаписывается каждую сессию |
| Трекер / субтрекер | Что делаем и в каком порядке | При заходе в фичу | Задача закрыта → строка статуса; фаза закрыта → трекер сворачивается |
| Спека сервиса | Как система устроена сейчас | При работе с подсистемой | Переписывается при изменении, не наслаивается |
| Журнал решений | Что выяснили на практике, чтобы не наступать повторно | По grep перед заходом в подсистему | Почти никогда — это накопленный капитал |
| Память (auto-memory) | Решения и предпочтения человека, доступы, договорённости о процессе | Индекс — всегда, файлы — по требованию | Факт устарел или переехал в репозиторий |

Память живёт в `~/.claude/projects/<проект>/memory/` — она **личная и не в репозитории**: на
машине коллеги её не будет. Всё, что нужно команде, кладётся в `docs/`; в память — только то, что
нельзя вывести из репозитория.

**Ключевое разделение, из которого следует всё остальное:**

- **Операционный лог** (сделал X, N тестов, коммит, список файлов) умирает с задачей. Его помнит
  git. В документации это второй слой правды, устаревающий независимо.
- **Durable-знание** (почему решено так, найденная ловушка, замеренная цена, грабли эксплуатации)
  переезжает в журнал решений или спеку. Этого в git не ищут.

```
Выводится из кода или git-истории?

└── НЕТ → Про конкретную подсистему?

                    Решение/предпочтение человека?  → память
                    Текущий план?                   → трекер
                    Где встали прямо сейчас?        → HANDOFF.md
```

## 4. Бюджеты и замер

**Мерить в символах, не в строках.** Плотность гуляет от 16 до 109 токенов на строку ✅ (замер по
55 документам): файл без переносов на «всего 138 строк» весил 15k токенов. Символы считаются на
любой ОС без зависимостей и линейно связаны с токенами: латиница и код ≈ 4 символа на токен,
кириллица ≈ 2.5–3.5. Точную цифру знает только `/context` — слэш-команды тебе недоступны, попроси
пользователя один раз выполнить её и прислать вывод. Ещё точный способ — `count_tokens` в
Messages API (нужен ключ). Вторая волна: сумма размеров файлов, которые сессия обязана прочитать,
чтобы начать фичу, — по 2–3 последним фичам.

| Что | Бюджет | Основание |
|---|---|---|
| Cold start целиком | ≤ 15–20k токенов | рекомендация |
| `CLAUDE.md` | ≤ 4k токенов ≈ 12 000 символов кириллицы ≈ 200 строк | Anthropic: «target under 200 lines»; наш замер ✅ |
| Файл правила в `rules/` | ≤ 4 000 символов | наше правило |
| `HANDOFF.md` | ≤ 3 000 символов, один экран | наше правило |
| Впрыск SessionStart-хука | ≤ 5k токенов | рекомендация |
| Трекер фичи | ≤ 4k токенов ≈ 12 000 символов — план, не архив | наше правило ✅ |
| Спека / документ | ≤ 8k токенов ≈ 24 000 символов, иначе делить или давать шапку-индекс | наше правило ✅ |
| Индекс памяти `MEMORY.md` | первые 200 строк или 25 KB — дальше **усекается молча** | документация |
| Описание скилла | ≤ 1 536 символов — дальше усекается в списке | документация |
| Любой `CLAUDE.md` / файл памяти | 40 000 символов — предупреждение CLI ✅; > 4 MiB не грузится вовсе | CLI, документация |

Ориентир ✅ (средний проект, ~15 фич, ~26k строк кода): cold start 9.2k токенов при 55 документах
и 45 файлах памяти — норма. Субтрекер закрытой фазы на 15k токенов — патология: он один дороже
всего старта сессии.

Текст, который грузится каждую сессию (`CLAUDE.md`, `rules`, `HANDOFF`), на английском стоит в
полтора-два раза дешевле, чем на русском. Язык выбирает владелец проекта — предложи, не навязывай.

## 5. Механика Claude Code

| Механизм | Когда грузится | Для чего |
|---|---|---|
| `.claude/CLAUDE.md` и корневой `CLAUDE.md` — равноправны, грузятся оба | Всегда | Только то, что нужно в любой сессии |
| Вложенный `CLAUDE.md` (`frontend/`, `backend/`) | При чтении файлов в этой директории | Крупная специфика самостоятельного подпроекта |
| `.claude/rules/*.md` с `paths:` | При чтении совпавшего файла (см. ниже) | **Рычаг разгрузки:** ловушки фреймворка, конвенции слоя, правила тестов — по маске |
| Skills `.claude/skills/<name>/SKILL.md` | Описание — всегда, тело — на вызов | Многошаговые процедуры: закрытие сессии, релиз, заведение сущности по рецепту |
| Память | Индекс — всегда, файлы — по требованию | Решения человека, правила работы, доступы |
| SessionStart-хук | Всегда | Ровно «где встали» + предупреждения стражей, ничего больше |
| Субагент (`Explore`, свои в `.claude/agents/`) | По вызову, в своём контексте | Объёмный поиск и чтение: в основной контекст приходит вывод, не файлы |
| MCP-серверы | Имена инструментов — всегда; схемы по умолчанию отложены и грузятся по требованию | Серверы, не нужные проекту, отключать: имена тоже стоят |
| Автокомпакция | При заполнении контекста, включена по умолчанию | Страховка, не план: короткие сессии через `HANDOFF` дешевле и точнее пересказа |

**Где держать `CLAUDE.md`.** Предпочтительно `.claude/CLAUDE.md`: всё хозяйство агента
(`CLAUDE.md`, `rules/`, `skills/`, `hooks/`, `settings.json`, `agents/`) в одной папке, корень
чистый. Цена — относительные ссылки становятся `../docs/…`; переписать разом при переносе.

### Как на самом деле работают `.claude/rules/` ✅

Проверено зондами на 2.1.238 и 2.1.266. Триггер узкий, и на нём легко построить правило, которое
молчит именно тогда, когда нужно.

| Вопрос | Ответ |
|---|---|
| `paths:` во frontmatter | Делает правило **условным**. Без `paths:` правило грузится всегда, как `CLAUDE.md` |
| `paths: ["**"]` | Тоже безусловное — не способ «включить везде дёшево» |
| Что триггерит | **Чтение файла инструментом Read**; `@`-упоминание в промпте; открытие в IDE |
| Что НЕ триггерит | Edit и Write, инструмент Grep, чтение через шелл (`cat`, `sed`, `grep`). Файл меняется — правило молчит |
| Семантика маски | `.gitignore` относительно корня проекта: `frontend/**` ≡ `frontend`; `*.css` — на любом уровне; слэши прямые, на Windows тоже |
| Новый файл правила | Подхватывается сразу, без перезапуска сессии |
| Сколько раз | Один раз за сессию на файл правила |
| Вложенность | Подпапки `.claude/rules/` обходятся рекурсивно |

**Следствие.** В `rules/` кладут знание для того, кто **открыл файл**: ловушки слоя, локальные
конвенции, «сначала посмотри вот сюда». Знание, нужное до чтения файлов (архитектура, команды,
протоколы), там бесполезно — решение будет принято раньше. Если ты работаешь преимущественно
шеллом (например, режим без разрешений предписывает читать через `cat`), правила не сработают
вовсе: проверь зондом и не заводи каталог, пока он бесполезен.

**Зонд (минута работы):** `.claude/rules/probe.md` с `paths: ["<маска>"]` и уникальным маркером →
прочитать файл под маской → файл вне её. Маркер обязан появиться ровно в первом случае. Тем же
приёмом проверяй любую гипотезу о загрузке контекста: зонд дешевле чтения документации.

**Не делать:**

- `@path`-импорты в `CLAUDE.md` — раскрываются на старте целиком (до четырёх уровней). Организуют
  текст, контекст не экономят. Разгрузка — `rules`, не импорты.
- Справочный материал и примеры в `CLAUDE.md` — читается всегда, нужен раз.
- Статусы задач в памяти — устаревают в тот же день, вторая правда. Статус только в трекере.

## 6. Протоколы — постоянный режим

Это ядро слежения. Сокращённая версия идёт в `CLAUDE.md` проекта (шаблон в §10.2); здесь полная.

**Старт сессии.** Хук впрыснул `HANDOFF.md` и предупреждения стражей → идти по handoff, читать
**только** названные точки входа. Веерное чтение памяти и `docs/` запрещено: нет в handoff →
Grep или субагент `Explore`, читать фрагментами, не целиком. Пользователь мог не увидеть
предупреждения хука — повтори их одной строкой в первом ответе с предложением, что сделать.

**Во время сессии — что отслеживать.** Заметил одно из этого → одна строка в конце ответа: факт +
предложение. Не лекция и не самодеятельность: чинить после согласия (исключение — `HANDOFF.md`,
он твой).

- файл вышел за бюджет §4: трекер, спека, `CLAUDE.md`, правило;
- второй источник правды: статусы или итоги дублируются в памяти, спеке, двух трекерах;
- протухший путь или ссылка в документе, который ты читаешь;
- документ, на который ниоткуда нет ссылки, или архив среди живого;
- durable-находка (грабли, цена, причина решения) всплыла по ходу → предложи запись в журнал
  сразу, не «в конце»;
- пользователь переключает тебя на другую фичу в той же сессии → предложи закрыть сессию по
  протоколу и открыть новую: контекст старой фичи новой не нужен;
- правило в `rules/`, которое не может сработать в текущем режиме работы (§5).

**Завершение сессии.**

1. Прогнать тесты, если менялся код.
2. Durable-находки → журнал решений / спека. Операционный лог — никуда, он в git.
3. Трекер: статус задачи, не пересказ сделанного.
4. **Перезаписать `HANDOFF.md`** по шаблону §10.4: где встали · сделано (2–4 пункта) · следующий
   шаг (первое конкретное действие) · точки входа (2–3 файла) · открытые нюансы. Один экран.
5. Коммит (+ пуш, если это часть протокола проекта).

**Закрытие фазы** — отдельным проходом, не «по ходу»:

1. Закрытые задачи вычистить из трекера — их описания и итоги уже в git. Закрытая фаза = одна
   строка статуса.
2. Durable перенести в журнал / спеку: **«durable перенеси, лог выкинь»**.
3. Память: слить дубли, снять устаревшее, подрезать индекс до 200 строк / 25 KB.
4. Перемерить cold start и вторую волну — цифрой подтвердить, что стало дешевле.
5. Предложить улучшения на следующую фазу: что раздулось, что разделить, что вынести в `rules`.

## 7. Стражи

Правила без автоматики держатся до первого аврала. Стражи — один скрипт на стеке проекта
(`tools/context_guard.*`), два режима: `--warn` (SessionStart-хук, всегда exit 0, короткий список
предупреждений) и `--check` (гейт вместе с тестами или pre-commit, exit 1 при нарушении).

| Страж | Что ловит | Заметки |
|---|---|---|
| **Размеры** | Файл над бюджетом §4, в символах: `CLAUDE.md`, `rules/*`, `HANDOFF.md`, трекеры, спеки | Индекс памяти скрипту недоступен (личный каталог) — его проверяешь ты при закрытии фазы |
| **Битые markdown-ссылки** | `[текст](путь)` в никуда в `docs/**`, `.claude/**`, `README.md` | Дёшево, ловится 100 %. Снимать `#якорь`, пропускать `http(s):` и `mailto:`, переваривать скобки в путях (`app/(public)/layout.tsx`) |
| **Пути в бэктиках** | `` `apps/foo/bar.py` `` к несуществующему файлу | ✅ На живом проекте ссылки были целы все (0 из 444), а путей в бэктиках гнило 35 — включая указатель в самом `CLAUDE.md`. Критерий: инлайн-код со `/` и расширением файла |
| **Документы-сироты** | `.md` в `docs/`, на который нет ни одной ссылки из `CLAUDE.md` или других документов | Только полный набор (§10.0) |
| **Отставание `HANDOFF.md`** | Коммиты после последнего изменения `HANDOFF.md` | `git log -1 --format=%ct -- docs/_dev/HANDOFF.md` против последнего коммита; на старте — «handoff отстаёт на N коммитов» |

**Исключения** — явный список рядом со скриптом, **с причиной на каждую строку**: исключение без
причины через полгода неотличимо от бага. Пропускать: блоки кода и инлайн-код с примерами
синтаксиса (`[текст](путь)` в таблице — ложное срабатывание ✅), пути с подстановками `<…>` и
`*`, отчёты-аудиты целиком (цитировать протухшие пути — их работа).

**Проверять стражей поломкой, а не наличием:** каждому подсунуть битую ссылку / раздутый файл /
несуществующий путь и убедиться, что он упал. Страж, который никогда не падал, обычно не работает.

Интерактивно то же показывают `/context` (что занимает контекст) и `/usage` (лимиты плана) — они
у пользователя, не у тебя.

## 8. Антипаттерны — что искать при обследовании (все встречены живьём ✅)

1. **Память ведёт второй трекер:** запись на 185 строк с итогами закрытых задач, коммитами и
   счётчиками тестов. Durable в ней — четыре абзаца.
2. **Файл сам признаёт дублирование:** начинается с «статусы сюда не дублирую, истина — в
   трекере» и следом перечисляет статусы всех фич.
3. **Индекс пересказывает вместо навигации:** строка индекса на 250 символов с выжимкой — второй
   слой правды. В индексе — имя + одна фраза «когда это читать».
4. **Навигация обрывается на папке:** карта ссылается на каталоги, а не на файлы → сироты.
5. **Архив среди живого:** спека снесённой подсистемы в одной папке с рабочими — читается как
   актуальная, пока не дойдёшь до шапки.
6. **Трекер как архив итогов:** 633 строки, 85 % — разбор закрытых задач; за 30 строк плана
   сессия платит 14k токенов.
7. **Правило чистки без момента срабатывания:** «прибираться после фазы» помнится до следующей
   фазы. Нужны привязка к событию + страж.
8. **Самая дорогая ложь — в файле, который читают чаще всего:** `CLAUDE.md` описывал модель,
   снесённую двумя фазами раньше. Проверка путей ловит это лучше ревью: 35 протухших путей прошли
   через десятки сессий незамеченными.

## 9. Чего сознательно не делаем

- Не оптимизируем cold start первым — он на виду, но дешевле второй волны.
- Не пишем детальные спеки на отложенное: детализируем перед заходом. Спека на то, что ещё
  поменяется, — выкинутый труд.
- Не заводим абстракций под один случай — ни в коде, ни в документации, ни в этом внедрении:
  масштаб по §10.0, а не «полный набор на всякий случай».
- Не полагаемся на автокомпакцию как на план: пересказ теряет именно durable.

## 10. Чек-лист внедрения

**10.0 Масштаб.** Выбрать по обследованию и назвать в плане.

- **Минимум** (любой проект): `CLAUDE.md` с протоколом (10.2) · `HANDOFF.md` (10.4) · журнал
  решений одним файлом (10.5) · страж размеров и отставания + хук (10.6–10.7).
- **Полный** (есть `docs/` от ~10 документов, или трекер на 3+ фичи, или несколько подсистем):
  плюс структура `docs/` (10.3) · стражи ссылок, путей и сирот в гейте · `.claude/rules/` после
  зонда (10.8) · протокол закрытия фазы.

Переход с минимума на полный — когда появился повод, не заранее.

**10.1 Замер исходного состояния** — cold start и вторая волна (§4) в символах, плюс `/context` от
пользователя. Без числа «раздуто» — вопрос вкуса, а «стало лучше» — недоказуемо.

**10.2 `.claude/CLAUDE.md`** — стек, команды, конвенции, карта документации (ссылки на файлы, не
на папки), протокол. **≤ 4k токенов.** Если `CLAUDE.md` уже есть — дополнить, не переписывать.
Блок протокола (пути адаптируй под проект):

```markdown
## Контекст и знание
- Старт: хук впрыснул HANDOFF.md и предупреждения стражей. Идти по HANDOFF, читать только
  названные точки входа. Веерное чтение docs/ и памяти запрещено: нет в HANDOFF → Grep или
  субагент Explore, читать фрагментами. Предупреждения хука повторить пользователю одной строкой.
- Перед работой в подсистеме: Grep `^### .*#<тег>` по docs/decisions/, затем спека в
  docs/services/<name>/.
- Куда писать: выводится из кода/git → никуда · как устроено → спека · почему и грабли →
  docs/decisions/ · план → трекер · где встали → HANDOFF.md · решение человека → память.
- Заметил файл над бюджетом, дубль правды, протухший путь, документ-сироту, смену фичи в той же
  сессии → одна строка предупреждения с предложением в конце ответа. Чинить после согласия.
- Конец сессии: тесты → durable в decisions/спеку → статус в трекере → перезаписать HANDOFF.md
  (один экран) → коммит.
- Закрытие фазы: отдельный проход по docs/_dev/context-playbook.md §6, затем перемерить.
```

**10.3 `docs/`** — плоско и по назначению: `architecture/` (как устроено + ADR), `services/<name>/`
(спеки), `decisions/` (журнал), `_dev/` (трекеры, `HANDOFF.md`, этот плейбук). Архив — в
`docs/_archive/`, не среди живого. Папки создавать под содержимое, не заранее.

**10.4 `docs/_dev/HANDOFF.md`** — шаблон, ≤ 3 000 символов:

```markdown
# HANDOFF · обновлено 2026-09-17 · фаза: <имя> · задача: <ID>
## Где встали
<одно предложение>
## Сделано в последней сессии
- <2–4 пункта>
## Следующий шаг
<первое конкретное действие>
## Точки входа
- `path/to/file` — зачем открывать
## Открытые нюансы
- <что не решено>
```

**10.5 Журнал решений `docs/decisions/<область>.md`** — завести сразу, с фиксированным форматом
(иначе grep не работает). ID = префикс файла + номер внутри файла, сквозная нумерация не нужна.
Теги — в строке заголовка, чтобы находиться одним Grep. **Индекс журнала не перечисляет записи**:
оглавление даёт `Grep ^###`. Триггер чтения стоит в протоколе `CLAUDE.md` (10.2) — без него
журнал наполняется, но не читается.

```markdown
### AUTH-3 · Refresh-токен нельзя ротировать в middleware #auth #session #middleware
2026-09-17
Грабли: <что случилось, что выяснили>
Решение: <что сделали и почему>
Не делать: <ловушка, в которую не наступать>
```

**10.6 Страж `tools/context_guard.*`** — на языке проекта, без внешних зависимостей, контракт из
§7. Вывод `--warn` — JSON для хука: `hookSpecificOutput.additionalContext` (для тебя: содержимое
`HANDOFF.md`, если он непустой, плюс предупреждения) и `systemMessage` (те же предупреждения,
чтобы их увидел пользователь). Нет handoff и предупреждений — вывод пустой. Гейт: добавить
`--check` в команду тестов или pre-commit. Каждому стражу подсунуть поломку (§7).

```json
{
  "hookSpecificOutput": { "hookEventName": "SessionStart", "additionalContext": "<HANDOFF + предупреждения>" },
  "systemMessage": "⚠ трекер docs/_dev/auth.md: 14 200 символов при бюджете 12 000 — свернуть закрытые задачи"
}
```

**10.7 Хук** в `.claude/settings.json` — общий для команды через git. Exec-форма: без шелла,
`${CLAUDE_PROJECT_DIR}` подставляется как строка, одинаково на macOS и Windows (в shell-форме
Windows без Git Bash запускает PowerShell, и bash-синтаксис ломается). `compact` в matcher не
включать: после компакции старый handoff вводит в заблуждение.

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|clear",
        "hooks": [
          {
            "type": "command",
            "command": "node",
            "args": ["${CLAUDE_PROJECT_DIR}/tools/context_guard.js", "--warn"],
            "timeout": 15
          }
        ]
      }
    ]
  }
}
```

Имя в `command` должно резолвиться одинаково на обеих ОС: `node`, `go`, `python` (на macOS без
venv это `python3` — проверить). Изменения `settings.json` подхватываются без перезапуска;
проверить хук новой сессией на каждой ОС, где живёт проект.

**10.8 `.claude/rules/`** — только после зонда §5 и только для знания «тому, кто открыл файл».
Одна маска — одно правило, ≤ 4 000 символов.

**10.9 Память** — индекс: одна строка на запись, тело в файлах; критерий записи — «нельзя вывести
из репозитория». Статусы и всё техническое — в `docs/`.

**10.10 Финал.** Переместить этот файл в `docs/_dev/context-playbook.md`, сослаться на него из
`CLAUDE.md` только в строке про закрытие фазы. Перемерить. Отчёт: цифры до/после, список
созданного и изменённого, что осталось за человеком.

**Порядок важен:** замер (10.1) → чистка второй волны, трекеры (§6 «закрытие фазы») → всё
остальное. Оптимизация cold start даёт меньше всего, хотя с неё хочется начать.
