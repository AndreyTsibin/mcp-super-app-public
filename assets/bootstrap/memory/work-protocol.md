## Сессии
- Одна сессия = одна атомарная задача.
- Старт: есть handoff (его подаёт SessionStart-хук) → идти по нему, читать только указанные
  точки входа. Нет → `MEMORY.md` + актуальный трекер/скоуп, без веерного чтения всей памяти.
- Держать контекст лёгким (~60% окна) — лучше свежая сессия, чем раздутая.

## Git и коммиты
- Коммитим в `develop`; `main` — только релизы (develop → main).
- Conventional Commits (feat/fix/docs/refactor/chore…), на английском.
- Чекпоинт-коммиты по ходу, на каждом завершённом куске — не свалкой в конце.
- Пуш — сразу после коммита, отдельного разрешения не спрашивать (если у репозитория есть
  remote). Незапушенный коммит виден только на одной машине.

## Завершение сессии

**Триггер — любая из фраз:** «заверши сессию» · «завершаем сессию» · «закрываем сессию» ·
«заканчиваем сессию» · «финализируй сессию» · «сворачиваемся» · «на сегодня всё» ·
«wrap up» / «end session». Срабатывает на смысл, а не на точную формулировку: просьба
подвести итоги и разойтись = протокол.

Протокол выполняется **целиком и подряд**, без подтверждения на каждом шаге. Не спрашивать
разрешения на коммит и пуш — оно дано этим правилом. Шаги не пропускать, даже если сессия
кажется пустой: «ничего не делали» — это тоже состояние, и его надо записать.

1. **Проверить, что начатое доведено до конца.** Пройтись по тому, что делали в сессии:
   нет ли забытой ветки логики, TODO в коде, наполовину переименованного символа.
   Незавершённое — назвать прямо, без сглаживания и без «доделаю в следующий раз».
2. **Если менялся код — прогнать проверки:** `‹тесты›`, `‹линт›`, `‹типы›`.
   Результат сообщить честно: упало — показать вывод и сказать, что упало, а не
   «всё зелёное с оговоркой». Красное чинить или явно оставить с объяснением почему.
3. **Если менялись данные или схема — снять бэкап** (`‹команда бэкапа›`) и назвать файл.
4. **Открытые вопросы — в память** (`‹memory / notes›`): то, что всплыло в сессии и
   переживёт её — решения, договорённости, грабли. Не дублировать то, что уже есть
   в репозитории, в CLAUDE.md или в git log.
5. **Перезаписать `.claude/HANDOFF.md`** — файл-эстафету для следующей сессии; его подаёт
   SessionStart-хук в начале следующей. **Не печатать его в чат**, только записать
   (решение 2026-07-25: файла достаточно). Объём — один экран. Структура:
   - что делали в этой сессии (по существу, а не список тул-коллов);
   - состояние: тесты/линт/типы, состояние базы и данных, что закоммичено;
   - **следующий шаг** — с чего начинается следующая сессия;
   - 2–3 точки входа: конкретные файлы со ссылками;
   - каверзы: грабли, о которые уже спотыкались, и запреты.
6. **Коммит и пуш** — внутри протокола, без отдельного разрешения. Сообщение по
   Conventional Commits, ветка — рабочая (`develop`), не релизная.

**Плейсхолдеры в ‹скобках› — подставить реальными командами этого проекта** при первом
завершении сессии (взять из `package.json` / `Makefile` / README) и переписать этот файл
уже с ними. Нет в проекте тестов или базы — так и записать «нет», а не оставлять скобки.

**Чего в протоколе делать нельзя:** запускать разрушающие команды ради «чистоты»
(сброс базы, сиды, удаление томов), затевать новую задачу «раз уж мы тут»,
рефакторить «на дорожку», сообщать шаг выполненным, если он падал.

## Автономия решений
- Реализацию (КАК построено: структура кода, паттерны, слои, зависимости, инфра/сеть, схема
  данных, нейминг, рефакторинг) Claude ведёт сам по best practices — в одну строку поясняя
  выбор, без развилочных вопросов.
- Андрею выносить ТОЛЬКО: (1) критичное/необратимое с ценой (деньги, прод-данные, безопасность,
  смена продуктовой стратегии); (2) UI — когда есть готовый визуал; (3) функционал — что фича
  даёт пользователю. Развилку реализации через AskUserQuestion НЕ выносить.

## Язык
- Код (имена, комментарии, коммиты) — английский.
- Общение и `docs/` — русский. UI-строки — через i18n (если проект локализуется).

## Стандарты кода
- Чисто и безопасно; никаких монолитов — дробить на модули.
- Оставлять подсказки будущему себе в коде, держать актуальными.
- Не усложнять: варианты взвесить внутри себя, выбрать лучший сам.
- Смотреть на решение под разными углами.

## Инструменты и знания
- Доку библиотек — всегда через Context7 (MCP), не из памяти (веса устаревают).
- Устаревшие знания (текущий год) — веб-поиск + доки Anthropic.
- Отладка в браузере — через Claude in Chrome.

## Память
- Держать в порядке, без мусора; выполненное удалять (история в коммитах).
- Всегда актуальный cold-start: по слову «продолжаем» ясно, с чего начать.

## Разработка
- Перед новой страницей/сервисом — проверить доку и план. Нет → сначала планируем.
- Локально до завершения; сервер — перед деплоем.
