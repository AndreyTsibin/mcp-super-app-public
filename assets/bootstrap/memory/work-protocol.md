## Сессии
- Одна сессия = одна атомарная задача.
- Старт: есть handoff (его подаёт SessionStart-хук) → идти по нему, читать только указанные
  точки входа. Нет → `MEMORY.md` + актуальный трекер/скоуп, без веерного чтения всей памяти.
- Держать контекст лёгким (~60% окна) — лучше свежая сессия, чем раздутая.

## Git и коммиты
- Коммитим в `develop`; `main` — только релизы (develop → main).
- Conventional Commits (feat/fix/docs/refactor/chore…), на английском.
- Чекпоинт-коммиты по ходу, на каждом завершённом куске — не свалкой в конце.
- Пуш — только с явного разрешения (исключение: протокол завершения сессии — там пуш штатный).

## Завершение сессии («Завершаем сессию»)
1. Тесты (если есть). 2. Закрыть вопросы сессии. 3. Открытые вопросы — кратко в память.
4. Записать handoff в `.claude/HANDOFF.md` (перезаписать) — его подхватит SessionStart-хук
   в начале следующей сессии. **В чат handoff НЕ выводить** (решение 2026-07-25: файла
   достаточно, ручное копирование блока из чата отменено). Компактно, карта на экран:
   где встали (задача + статус) · сделано (2-4 пункта) · следующий шаг (первое конкретное
   действие) · точки входа (2-3 ссылки на файлы/спеки/память) · открытые нюансы.
5. Коммит + **пуш** — в протоколе завершения оба штатные шаги, отдельного разрешения не
   ждать (вне протокола завершения пуш по-прежнему только с явного разрешения).

## Автономия решений
- Реализацию (КАК построено: структура кода, паттерны, слои, зависимости, инфра/сеть, схема
  данных, нейминг, рефакторинг) Claude ведёт сам по best practices — в одну строку поясняя
  выбор, без развилочных вопросов.
- Андрею выносить ТОЛЬКО: (1) критичное/необратимое с ценой (деньги, прод-данные, безопасность,
  смена продуктовой стратегии); (2) UI — когда есть готовый визуал; (3) функционал — что фича
  даёт пользователю. Развилку реализации через AskUserQuestion НЕ выносить.

## Язык
- Код (имена, комментарии, коммиты) — английский.
- Общение и `docs/` — русский. UI-строки — через i18n (если проект локализуется).

## Стандарты кода
- Чисто и безопасно; никаких монолитов — дробить на модули.
- Оставлять подсказки будущему себе в коде, держать актуальными.
- Не усложнять: варианты взвесить внутри себя, выбрать лучший сам.
- Смотреть на решение под разными углами.

## Инструменты и знания
- Доку библиотек — всегда через Context7 (MCP), не из памяти (веса устаревают).
- Устаревшие знания (текущий год) — веб-поиск + доки Anthropic.
- Отладка в браузере — через Claude in Chrome.

## Память
- Держать в порядке, без мусора; выполненное удалять (история в коммитах).
- Всегда актуальный cold-start: по слову «продолжаем» ясно, с чего начать.

## Разработка
- Перед новой страницей/сервисом — проверить доку и план. Нет → сначала планируем.
- Локально до завершения; сервер — перед деплоем.
