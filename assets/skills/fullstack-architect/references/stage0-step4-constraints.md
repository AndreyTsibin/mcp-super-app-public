# Шаг 4: Бюджет, сроки и команда

Последний шаг перед созданием PRD! Нужно понять твои ограничения.

## Вопросы про ресурсы (2-3 мин)

### 1. Какой бюджет на разработку?

**Выбери вариант или укажи свой:**

💵 **\$0 (делаю сам/своими силами)**
- Подойдёт: Если ты или кто-то в команде умеет программировать
- Риски: Может затянуться, если опыта мало

💵 **\$2,000 - \$10,000**
- Подойдёт: Можно нанять фрилансера или младшего разработчика
- Риски: Качество зависит от исполнителя

💵 **\$10,000 - \$50,000**
- Подойдёт: Можно нанять опытную команду или агентство
- Риски: Минимальны, если подрядчик проверенный

💵 **\$50,000+**
- Подойдёт: Крупный проект с high-quality кодом
- Риски: Переплата если scope небольшой

**Важно:** Я подберу технологии и архитектуру под твой бюджет.

> ⏱️ Реальный срок MVP зависит от СЛОЖНОСТИ, а не от бюджета — посчитаю его на предварительной оценке (сразу после PRD), диапазоном с буфером. Здесь сроки не привязываю, чтобы не давать ложный якорь.

---

### 2. Дедлайн для MVP?

**Когда хочешь запуститься?**

⏰ **2-4 недели** (экстремально быстро)
- Возможно только для простых проектов
- Минимум функций
- Высокий риск technical debt (костыли в коде)

⏰ **1-2 месяца** (оптимально для MVP)
- Самый популярный вариант
- Успеешь сделать качественно
- Можно включить 5-7 ключевых функций

⏰ **3-6 месяцев** (долгосрочный проект)
- Если важно качество с первого дня
- Можно добавить больше функций
- Риск: можешь потерять мотивацию или деньги кончатся

⏰ **Нет дедлайна** (когда будет готово)
- Хорошо для side-проектов
- Плохо для бизнеса (нет urgency → нет результата)

**Моя рекомендация:** 1-2 месяца — золотая середина.

### 3. Кто будет разрабатывать?

**Выбери вариант:**

👤 **Только я (solo founder)**
- Плюсы: Полный контроль, не нужно платить
- Минусы: Долго, нужны навыки программирования
- Совет: Используй максимально готовые решения (Bubble.io, Webflow + Airtable)

👥 **Я + 1-2 человека** (друг/партнёр/фрилансер)
- Плюсы: Можно разделить задачи (один frontend, другой backend)
- Минусы: Нужна координация
- Совет: Чёткое распределение ролей

👥 **Команда 3-5 человек**
- Плюсы: Быстрая разработка, можно делать сложные вещи
- Минусы: Дорого, нужен тимлид
- Совет: Разбить на роли (frontend, backend, дизайнер, тестировщик)

🤖 **Claude Code + я**
- Плюсы: Автоматическая генерация кода, быстро
- Минусы: Нужно проверять код, может быть technical debt
- Совет: Идеально для прототипов и MVP

**Моя рекомендация:** Если бюджет \$0 → попробуй Claude Code для MVP, потом наймёшь профи для production.

---

### 4. Какие технологии ты/команда уже знаете?

**Это важно!** Лучше использовать знакомые технологии, чем учить новые.

**Примеры:**

✅ "Я знаю Python, немного JavaScript"
✅ "Мой друг разработчик, работает с React и Node.js"
✅ "Никто не умеет программировать, но готовы учиться"
✅ "Хотим без кода (no-code), типа Bubble или Webflow"

**Если не знаешь технологий:** Не страшно! Я подберу самые простые и популярные для твоего случая.
