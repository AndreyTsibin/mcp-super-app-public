# Технический стандарт сборки

> Читается на шаге контента и сборки страниц (`docs/landing-flow.md` → Флоу, шаг 4).
> Как устроен проект, где данные, как собрать страницу, как добавить свою секцию.
> Значения цветов и шрифтов — только из `src/styles/theme.css` (см. design-standard).

**Стек:** Astro 5 (статическая сборка, `output: 'static'`), CSS на токенах, инлайн-JS
там, где он нужен, PHP для приёма заявок. UI-фреймворков нет и не нужно.
**Шрифты:** Google Fonts, ровно 2 семейства из темы, подключаются через `fontsHref`
в `BaseLayout` (`display=swap`, только нужные веса).
**Иконки:** инлайн-SVG прямо в компоненте, стиль библиотеки — filled, `viewBox="0 0 24 24"`,
`fill="currentColor"`. Нужна новая — тулы `search_icons` → `get_icon` (lucide — общие
UI-иконки, simple-icons — бренд-логотипы). Внешний CDN не подключать.

## Структура проекта

```
<корень проекта>/
├── astro.config.mjs        # site: боевой домен — ПОДСТАВИТЬ (canonical + OG)
├── package.json
├── public/                 # копируется в dist/ как есть
│   ├── send.php            # приём заявок (docs/ЗАЯВКИ-инструкция-для-Claude.md)
│   ├── favicon.svg
│   └── assets/
│       ├── lead-form.js    # логика формы — контракт заявок, не переписывать
│       └── img/            # картинки сайта (генерация + фото клиента)
├── src/
│   ├── pages/              # КАЖДЫЙ файл = маршрут
│   │   ├── index.astro     # главная (образец под ремонт техники — перепиши)
│   │   ├── uslugi/…        # внутренние страницы услуг
│   │   ├── privacy.astro   # политика 152-ФЗ
│   │   ├── kit.astro       # полигон секций (noindex) — удалить перед сдачей
│   │   └── themes.astro    # выбор темы (noindex) — удалить перед сдачей
│   ├── layouts/BaseLayout.astro   # <head>, мета, шрифты, модалка, скрипты
│   ├── components/         # библиотека из 21 секции
│   ├── data/
│   │   ├── demo.ts         # демо-контент — заменить своим и удалить
│   │   └── themes.ts       # кандидаты тем для /themes — удалить перед сдачей
│   ├── styles/
│   │   ├── tokens.css      # КОНТРАКТ: имена токенов + база. Правится редко и осознанно
│   │   └── theme.css       # ЗНАЧЕНИЯ темы проекта
│   └── lib/typography.ts   # nbsp() — русская микротипографика
├── docs/                   # стандарты (эта папка) — не прод
└── dist/                   # результат npm run build — это и уезжает на хостинг
```

Порядок стилей в `BaseLayout` (`tokens.css` → `theme.css`) менять нельзя: тема
перекрывает контракт, не наоборот.

## Данные отдельно от разметки

Контент живёт в `src/data/<проект>.ts` и типизирован — так его правит и человек,
и агент, не трогая разметку:

```ts
export const site = {
  brand: 'Название',
  phone: '+7 495 123-45-67',
  workHours: 'Пн–Вс 7:00–23:00',
  nav: [{ label: 'Услуги', href: '/uslugi/…' }],
  hero: { title: '…', subtitle: '…', bullets: [...] },
  // …
};
```

Образец полей — `demo.ts` (демо-ниша). Скопируй структуру, наполни своим,
демо-файл удали вместе с `kit.astro` и `themes.astro` — они на него ссылаются.

## Сборка страницы

Страница = `BaseLayout` + секции по порядку. Пропсы читай в `interface Props`
самого компонента — там же комментарии, чего секция ждёт:

```astro
---
import BaseLayout from '../layouts/BaseLayout.astro';
import Header from '../components/Header.astro';
import Hero from '../components/Hero.astro';
import { site } from '../data/site';
---
<BaseLayout title={`${site.hero.title} — ${site.brand}`} description={site.hero.subtitle}>
  <Header logo={site.brand} phone={site.phone} workHours={site.workHours} nav={site.nav} />
  <Hero title={site.hero.title} subtitle={site.hero.subtitle} phone={site.phone} variant="split" />
  …
</BaseLayout>
```

Правила композиции:
- Ровно один `<h1>` на странице — его даёт `Hero` (и подменяет `?h=`).
- `id` секции = якорь для меню; ссылки в `nav` на якоря пиши как `#id`.
- `alt={true}` чередует фон; ритм — см. `docs/landing-spec.md`.
- Все текстовые props прогоняются через `nbsp()` внутри секций — вручную вставлять
  неразрывные пробелы не надо.
- Кнопка, открывающая форму, — с атрибутом `data-open-modal`; модалка одна и уже
  в `BaseLayout`.

## Маршруты и многостраничник

`src/pages/uslugi/remont.astro` → `/uslugi/remont`. Никакой конфигурации не нужно.

- **Canonical на каждой странице обязателен** — иначе поисковик склеит страницы как
  дубли. `BaseLayout` строит его сам из `site` в `astro.config.mjs`; чтобы это
  работало, домен должен быть подставлен.
- Свой `title` и `description` у каждой страницы — не копия главной.
- Ссылки — корневые (`/uslugi/…`, `/privacy`), не относительные и не `*.html`.
  После переименования страницы проверь ссылки на неё во всех компонентах: типовая
  ловушка — политика в футере и в чекбоксе согласия.
- Служебные страницы — `noindex={true}`.

## Как править и добавлять секции

**Поменять данные** — в data-файле. **Поменять композицию** — `variant` и порядок
секций. **Поменять вёрстку** — правь компонент: это разрешено, если правка читает
токены, а не хардкодит значения.

Новая секция — по образцу соседней (возьми ту, что ближе по структуре):
1. `src/components/MySection.astro`, `interface Props` c `title`/`subtitle`/`eyebrow`/
   `variant`/`alt`/`id`, как у остальных.
2. Обёртка — `<section class:list={['section', { 'section--alt': alt }]} id={id}>`
   и `<div class="container">` внутри.
3. Заголовки — тегами `h2`/`h3`: размеры и веса уже заданы в `tokens.css`, свой
   `font-size` на них не вешать.
4. Стили — в `<style>` компонента, значения только из токенов.
5. Тексты — через `nbsp()`.
6. Добавь секцию на `/kit`, пока полигон ещё жив: там её видно во всех вариантах.

## Картинки

Готовятся на шаге 5 флоу (`docs/image-standard.md`), лежат в `public/assets/img/`
оптимизированными (`optimize_images`: webp, ресайз). В разметке всё уже сделано
библиотекой: hero — `fetchpriority="high"` без lazy, остальные — `loading="lazy"`.
От тебя нужны:
- путь (`/assets/img/…` — от корня `public/`, не `./`),
- осмысленный русский `alt` (для декоративных фонов — пустой, там `aria-hidden`).

Никаких внешних картиночных сервисов и hotlink — всё локально.

## SEO-мета

Задаётся пропсами `BaseLayout`: `title` (оффер + город), `description` (выгода,
до ~160 символов), `ogImage` (обычно hero), `ogType`, `noindex`. Остальное —
`lang="ru"`, viewport, canonical, Open Graph, favicon, `theme-color` — лейаут
проставляет сам.

## Мобильная адаптация

Библиотека mobile-first, брейкпоинты 768/1024, всё корректно на 320px. Что остаётся
на тебе:
- **первый экран на 375px** = оффер (`<h1>`) + подзаголовок + CTA (в urgency — ещё
  и кликабельный телефон). Тяжёлый `Hero` с картинкой и длинным подзаголовком
  выталкивает кнопку за фолд — проверяй на 375px перед сдачей;
- **длинные секции**: если карточек заметно больше 5, бери вариант с каруселью
  (`slider`) или сократи список — длинное полотно на мобиле утомляет;
- CTA на мобиле — на всю ширину, минимум 52px по высоте (в `.btn` уже так,
  не переопределяй меньшим).

## Сборка

```
npm run dev      # разработка, порт из .claude/launch.json
npm run build    # прод-сборка в dist/
npm run preview  # посмотреть собранное
```

`dist/` — то, что уезжает на хостинг: HTML всех страниц, `_astro/*.css|js` с хешами
в именах, всё содержимое `public/` (включая `send.php`) как есть. Исходники, `docs/`
и `node_modules/` на хостинг не идут.
