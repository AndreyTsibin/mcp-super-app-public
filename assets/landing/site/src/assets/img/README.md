# src/assets/img — сюда кладутся картинки сайта

Всё, что лежит здесь, Astro обрабатывает при сборке: режет по ширинам, отдаёт
webp и проставляет `srcset` / `sizes`. Один файл-исходник → набор вариантов,
браузер берёт подходящий под экран. Ничего настраивать не нужно — достаточно
подключить картинку **импортом**, а не строкой:

```ts
// src/data/<проект>.ts
import hero from '../assets/img/hero.webp';
import master from '../assets/img/master.webp';

export const content = {
  hero: { image: hero, imageAlt: 'Мастер настраивает станок в цеху' },
  team: { members: [{ name: 'Игорь', photo: master }] },
};
```

Импорт обязателен: строка `'/assets/img/hero.webp'` тоже работает, но она —
путь в `public/`, и такие файлы Astro не трогает вообще (одна картинка на все
экраны). Строкой подключают только то, что нельзя обработать: SVG-заглушки
шаблона и внешние URL.

## Что класть

- Кадры из `create_image` (`save_dir: src/assets/img`).
- Фото от клиента — они приоритетнее генерации, особенно в trust-нишах.

Прогони и то и другое через `optimize_images(paths: ["src/assets/img"])`:
тул нормализует исходник (webp, ширина до 1920, EXIF-поворот телефонных фото),
а нарезку по ширинам дальше делает Astro. Исходник шире 1920 и тяжелее ~300 КБ
замедляет сборку и раздувает репозиторий без выигрыша в качестве.

Подробности пайплайна — `docs/image-standard.md`.
